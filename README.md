# Лиза ЖЁСТКИЕЙ ТРЕНЖЁР + Вайб

Визуальная основа сайта для подготовки к ОГЭ и ЕГЭ по истории и обществознанию.

## Что уже заложено

- Главная страница ученика с выбором предмета и экзамена.
- Страница `Регистрация/вход`.
- Учительский макет `/teacher` со списком учеников, поиском и сортировкой.
- Учитель может сменить пароль в своём кабинете. Перед публикацией обязательно замени прежний тестовый пароль.
- `/teacher` закрыт входом учителя через подписанную cookie-сессию.
- После входа в шапке вместо `Регистрация/вход` показывается имя аккаунта.
- После регистрации ученик сразу получает сессию, и в шапке показывается его имя.
- Для вошедших учеников и учителя в шапке есть кнопка `Выйти`.
- Учитель может создавать приглашения, а ученик регистрируется по ссылке `/register/[code]`.
- Кнопка создания приглашения сразу копирует полную ссылку регистрации в буфер обмена.
- В локальной Windows-разработке сервер дополнительно кладёт ссылку в системный буфер компьютера.
- Ученики берутся только из защищённой базы данных.
- Подключение к Supabase через переменные окружения.
- SQL-схема базы лежит в `supabase/schema.sql`.

## Как лучше делать приглашения

Лучший вариант для настоящего сайта: специальная ссылка-приглашение, например `/register/LZ-8K2P-MR91`.

Почему так удобнее:

- ученику не нужно вручную переписывать код;
- код всё равно остаётся внутри ссылки;
- учитель может скопировать ссылку и отправить ученику;
- позже можно добавить срок действия и запрет повторного использования.

Поле для ручного ввода кода тоже стоит оставить как запасной вариант.

## Как включить настоящую базу данных

1. Открой Supabase.
2. Перейди в `SQL Editor`.
3. Создай новый запрос.
4. Вставь содержимое файла `supabase/schema.sql`.
5. Нажми `Run`.

После этого страница `/teacher` сможет проверять вход учителя и брать учеников из Supabase. Если база недоступна, список учеников не показывается.

Если таблицы уже созданы, но нужно добавить только проверку входа учителя, можно выполнить короткий файл `supabase/teacher-auth.sql`.

Локальные переменные лежат в `.env.local`, этот файл не отправляется в GitHub. Пример переменных есть в `.env.example`.

## Перед публикацией в интернете

1. Применить `node scripts/apply-publication-security.mjs` — закрыть публичное чтение учеников и приглашений, отключить общедоступную проверку пароля учителя и старые тестовые пароли учеников.
2. В кабинете учителя сменить прежний пароль на уникальный (не менее 16 символов). После смены старые сеансы учителя перестанут работать.
   Проверить результат командой `node scripts/check-publication-security.mjs`: `readyToPublish` должно быть `true`.
3. Настроить на хостинге `SUPABASE_DB_URL` и `AUTH_SESSION_SECRET` как секретные переменные. Не помещать их в GitHub и не отправлять в чат.
4. Проверить вход, список учеников, приглашения и редактирование заданий уже по HTTPS-адресу сайта.

Бесплатный тестовый сайт не считать закрытым только потому, что его адрес никому не сообщали.

## Управление заданиями

В кабинете учителя кнопка «Управление заданиями» открывает `/teacher/tasks`.
Можно искать и редактировать все текущие задания обществознания ЕГЭ и ОГЭ,
добавлять задания ЕГЭ и задания ОГЭ №1, загружать PNG/JPG/WebP до 5 МБ.
Черновики и удалённые задания не выдаются ученикам. Удалённое можно восстановить
в черновик, затем опубликовать. Изменения и история предыдущих версий хранятся
в Supabase; исходные файлы импорта сохраняются. Конкурирующее сохранение из
двух вкладок отклоняется, чтобы не перезаписать чужие изменения.

На новой базе после основной схемы применить миграцию:

```sh
node scripts/apply-task-management.mjs
```

Проверка управления заданиями на запущенном локальном сервере (создаёт и
удаляет только собственные тестовые записи):

```sh
node scripts/test-task-management.mjs
```
